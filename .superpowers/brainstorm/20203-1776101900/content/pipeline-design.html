Section 1: New Pipeline Architecture

LLM is primary. Rules are compiled from LLM outputs. Fast-path grows over time.

Ongoing Email Classification Flow
📨 New email arrives
│
▼
① Pattern cache check
(LLM-compiled rules, in-memory)
↳ match →
Rule result ✓ skip LLM
↳ no match
↓
② Domain rule check
(amazon.in, swiggy.in, HDFC…)
↳ match →
Rule result ✓ skip LLM
↳ no match
↓
③ LLM: classify + extract
label · amount · merchant · category · date
│
↳ Save transaction
↳ async: generate rule ↓
Rule Generation Loop
│
Step 1: Template regex
merchant + label keywords
→ test against same email
↳ match →
Save rule
source: llm_generated ✓
↳ no match
↓
Step 2: LLM writes regex
"Write a regex that matches this email"
→ test against same email
↳ match →
Save rule
source: llm_written ✓
↳ no match →
Drop rule
txn still saved ✓
Key insight: Pattern cache grows with every LLM call. After bootstrap, most emails hit the cache and skip LLM entirely. Cost drops over time, accuracy stays high.
