When a generated rule fails its self-test — what should happen?

Current system: rule is silently dropped. You want LLM to improve it. How?

A

Drop & Move On

If the auto-generated regex doesn't match the trigger email, discard it. LLM result is still saved to the transaction. Rule generation is best-effort — not every email needs a rule.

Pros

  • Simple, no extra LLM calls
  • Only high-quality rules saved

Cons

  • Miss opportunities for rules on unusual patterns
B

LLM Writes the Rule Directly (recommended)

Instead of code generating the regex, ask the LLM: "Given this email and its classification, write a regex that matches it." LLM produces the pattern. We test it. If it matches → save. If not → drop.

Pros

  • Rules tailored to actual email text
  • LLM understands context — e.g. "INR X debited to MERCHANT"
  • Higher match rate than template regexes

Cons

  • 1 extra LLM call per rule generated
C

Retry with Broader Template

Keep code-generated templates but try progressively looser patterns: merchant-only → amount+merchant → label keywords only. Stop at first match. No extra LLM call.

Pros

  • Zero extra cost
  • Deterministic

Cons

  • Looser rules → more false positives
  • Still brittle vs. real-world SMS/email variation
