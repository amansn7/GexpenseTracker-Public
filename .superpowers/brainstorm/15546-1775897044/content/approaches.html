3 Architectural Approaches

All use Python + FastAPI + Postgres. Difference is how services are split.

A

Monolith ⭐ Recommended

Single FastAPI app. APScheduler runs Gmail polling in-process every 2hr. Dashboard + API served from same app. One process, one repo, one deployment. Simple to build and run.

Pros

  • Minimal ops complexity
  • Easy local dev
  • Perfect for single user

Cons

  • Scheduler dies if API crashes
  • Harder to scale later (not a real concern for personal tool)
B

Monolith + Celery Worker

FastAPI app for API/dashboard. Separate Celery worker process for Gmail polling + classification. Redis as broker. Two processes.

Pros

  • Worker isolated from API
  • Retry logic built-in
  • More resilient

Cons

  • Redis dependency
  • More complex setup
  • Overkill for 2hr polls
C

Microservices

Separate services: email-poller, classifier, API, frontend. Each independently deployable. Docker Compose wires them together.

Pros

  • Each service has single responsibility
  • Independent scaling

Cons

  • High build overhead
  • Network hops between services
  • Way too much for a personal tool
